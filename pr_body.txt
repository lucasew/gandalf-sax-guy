This PR resolves a technical debt issue regarding code duplication in `index.html`.

By extracting the mathematical playback rate clamping logic (`Math.abs`, `Math.min`, `Math.max`) into a reusable `calculatePlaybackRate` function, we DRY up the synchronization logic and make the main `tightSync()` function easier to read.

### Assumptions
- The clamping mathematical logic does not rely on closures and can safely be isolated into a pure helper function mapping inputs `error`, `maxCorrection`, `gain`, and `threshold` to a final playback rate modifier.
- Applying this helper structure identically for both the audio and video sync logic retains exact behavior as previously observed.

### Alternatives Not Chosen
- Continuing to inline these duplicate mathematical lines to avoid "pre-optimization", but code-duplication scanning engines caught this so it was prioritized.
- Pulling out generic math functions (like a general `clamp` function) instead of a specific playback rate calculation function.

### How To Pivot
- If a future requirement demands distinct sync clamping behavior entirely for video versus audio, we can either pass in another parameter or revert the function into two specialized methods.
